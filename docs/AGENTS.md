# KnowledgeOS Documentation Contract

- Treat `CAPABILITIES.md` as the user-designated top-level behavior and acceptance specification, supplemented by user intent and Blueprint system constraints without changing Core contracts or schemas.
- Add a document here only when a slice needs maintained guidance that does not fit the three spec documents; never add status, history or evidence documents.
- Keep progress and evidence in `PROJECT_STATE.md` only.
- Keep the sole wiki explanation originals in the Sites monorepo's `knowledgeos/_source/`, not in this Operation's documentation tree.
- Keep specification authority here and treat generated Sites status pages as views, never a second current-state ledger.
