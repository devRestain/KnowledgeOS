# Team and Officer bindings

[`ops/config/team-catalog.json`](../ops/config/team-catalog.json) defines seven dedicated Manager identities and candidate standalone Officers. [`ops/config/work-methods.json`](../ops/config/work-methods.json) defines their method contracts. The owner admits either a Team with its exact Manager or one standalone Officer. Shared teammate definitions can be reused only through a new owner-local executor and Profile binding.

An admitted Work pins its method digest, source ResourceReference, Profile, Graph lineage, criteria and budget. Its effective permission is the intersection of owner policy, Work scope, method stage and trusted Runner binding. A client cannot select actor, root or binding through MCP arguments. Explicit user pins have no silent fallback. Every effect uses the owner journal and can require reconciliation before continuation.

`vaultmcp` exposes all tool names to a general client, but Work-only calls require a trusted owner-issued context. A producing Manager, teammate or Officer cannot submit an independent EvalOfficer assessment for its own artifact. Human decision and canonical apply are distinct owner actions.

`application/normalization_work.py` supplies one NormalizationOfficer executor with a provider-free default and an explicitly model-bound mode, plus a separately implemented deterministic EvalOfficer. The native binding pins actual module bytes and, in model mode, the native host adapter and exact provider/model. Its one-task Graph uses the adopted deterministic orchestration contract, not a claimed LangGraph runtime. The evaluator freshly checks exact source/proposal bytes, completed effect receipt, admitted criterion, recorded model evidence when present, and pending human gate before Owner completion. `make officer-smoke` and `make model-officer-smoke` exercise these modes through real Temporal and authenticated Owner HTTP in disposable roots. Use `PROJECT_STATE.md` for observed results.

`application/curation_work.py` separately supplies one exact Curation Team binding: dedicated Manager, triage and native model normalizer, with fresh deterministic EvalOfficer checks. Its `curation_temporal.py`/`curation_workflow.py` binding uses the official Temporal-LangGraph plugin with separate per-stage Activities rather than reusing the Officer Workflow. The selected Team module bytes, preview package versions, host adapter, method and local executor/Profile pairs are pinned; ordered full source pages and actual owner receipts are evidence, not model completion text. Exact committed-result recovery additionally requires a trusted stopped-producer check and durable original-actor intent before its native Update; it never grants another model or proposal call. See `docs/RUNTIME.md` for the disposable commands and remaining general recovery/control exclusions.

`application/research_work.py` supplies the separate bounded `evidence-research` Team: `knowledgeos.research_manager`, `knowledgeos.retriever`, `knowledgeos.synthesizer` and an independent EvalOfficer. `research_admission` pins one exact source and question, method `knowledgeos.cited_research_team`, explicit executor/Profile assignments, one immutable sequential Graph, one segment and two Profile invocations. Existing `document_enhancement` intake selects this constructor only when its trusted composition supplies `native_research_runner_binding`; a generic template or an installed read-only Profile does not supply the native admission. `research_temporal.py` and the module-level `research_workflow.py` register `KnowledgeOSEvidenceResearchV1` with separate Manager, retrieval, synthesis and assessment Activities under the same pinned official plugin packages. Research and Curation method/Team bindings cannot borrow each other's native route.

Both Research teammate Profiles invoke native Hermes. Retrieval exposes only `knowledge_search`, `knowledge_retrieve`, `knowledge_read` and `citation_verify`; successful zero-match queries do not replace the required complete ordered source-page reads. Synthesis receives the freshly validated immutable evidence bundle and exposes only `artifact_submit`. It submits one `document_enhancement_report`, not a normalizer proposal or a canonical effect. `ops/clients/hermes/native_research.py` owns these request, prompt and trace semantics; the shared `native_runtime.py` owns fresh-process isolation, exact configured provider transport and scoped MCP mechanics. Its adapter digest hashes the canonical object containing the raw-byte SHA-256 values of both files (`adapter_sha256`, `runtime_sha256`). The existing three-tool `native_officer.py` contract is unchanged. Independent deterministic assessment reopens exact source/generation/citations, per-improvement citation indices, explicit gaps, artifact bytes and successful effect receipt, and is repeated before final owner commit. It checks evidence integrity and coverage, not claim truth or model self-certification.

`make research-team-smoke` exercises this exact Team with two actual configured model invocations, four native Activities and authenticated Owner report/evidence export; the [disposable native evidence](../../../Tmp/knowledgeos-native-research-2026-10-31/trace-run.json) is distinct from earlier read-only citation workflows. Use `docs/RUNTIME.md` for prerequisites, create-only evidence output and limits. No Research retry, recovery, human control, production service or native Obsidian adoption follows from that bounded pass.

`application/curation_continuation.py` selects a separate digest-pinned method on the same two-Profile Team. An initial triage Graph leaves the Pending criterion `not_run`; an independent owner-admitted assessment and RemainingWork authorize only the exact normalizer successor. Each segment has one Profile and immutable predecessor/trigger lineage. Cumulative segment, repeated-gap and Profile budgets stop exhausted work durably without invoking the model. `curation_continuation_temporal.py`/`curation_continuation_workflow.py` use a separate method-bound Workflow with two official plugin graphs. `make team-continuation-smoke` covers success and budget stops, not production adoption or combined continuation/recovery.

The trusted `control_checkpoint=True` admission flag selects a separate native control route on the continuation method. `CurationRunControl` opens a revision-bound wait only after independent initial evidence and before any model/proposal effect. CANCEL terminates at that boundary or while paused. One applied PAUSE produces a fresh paused target; only exact applied RESUME authorizes the existing immutable successor. Both receipts survive idle Worker reconstruction without resetting evidence, lineage or consumed budgets. Native Activities and owner commits reauthorize current authority; SDK-free MCP/proposal checks independently require the durable release proof. `make team-control-smoke` covers cancellation plus actual model continuation after resume, historical receipts and client response-loss reconciliation, not generic or in-flight control.

The controlled binding additionally permits one owner-prepared/adopted Continue-As-New at its idle checkpoint. A separate durable handoff pins the original Work and command snapshots and authorizes one replacement native Run, without rewriting the original checkpoint target or logical IDs. Pending commands, cached applied receipts, immutable evidence and consumed budgets survive; the replacement does not rerun initial Profiles. `make team-rollover-smoke` exercises pending RESUME plus cached PAUSE, native Run fencing, the existing successor and replay of both histories. Rollover does not widen Profile authority or grant a new segment budget.

Installed role homes or read-only model access alone do not grant Work authority. The Officer and Curation normalizer adapter exposes only its exact three owner-bound tools; Research uses the separate stage grants above. Neither adapter can approve/apply or select a different Work through arguments. External model mode refuses local-only, denied and confidential sources. Model traces remain owner-private journal evidence rather than an automatic status-export surface. Production Team execution, model-based assessment, cross-Operation reuse and native Obsidian adoption remain separate contracts and evidence. Computer Use is left to the user.
