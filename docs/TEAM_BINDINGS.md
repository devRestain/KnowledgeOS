# Team and Officer bindings

[`ops/config/team-catalog.json`](../ops/config/team-catalog.json) defines seven dedicated Manager identities and candidate standalone Officers. [`ops/config/work-methods.json`](../ops/config/work-methods.json) defines their method contracts. The owner admits either a Team with its exact Manager or one standalone Officer. Shared teammate definitions can be reused only through a new owner-local executor and Profile binding.

An admitted Work pins its method digest, source ResourceReference, Profile, Graph lineage, criteria and budget. Its effective permission is the intersection of owner policy, Work scope, method stage and trusted Runner binding. A client cannot select actor, root or binding through MCP arguments. Explicit user pins have no silent fallback. Every effect uses the owner journal and can require reconciliation before continuation.

`vaultmcp` exposes all tool names to a general client, but Work-only calls require a trusted owner-issued context. A producing Manager, teammate or Officer cannot submit an independent EvalOfficer assessment for its own artifact. Human decision and canonical apply are distinct owner actions.

`application/normalization_work.py` retains a standalone NormalizationOfficer with a provider-free default and explicit native model mode, plus deterministic integrity assessment. Its one-task Graph is distinct from Team orchestration. Native mode pins the role-capable runtime and complete SOUL policy; the individual invocation records its actual provider/model. Fresh source/proposal/effect/human-gate checks remain required. `make officer-smoke` and `make model-officer-smoke` exercise those separate modes; neither establishes the autonomous Team acceptance tracked in `PROJECT_STATE.md`.

Team registrations are selected by admitted method, not by one global binding per Team ID. Curation's normalization, continuation, cited-draft and steering methods can share their dedicated Manager while retaining different exact method/roster/runtime bindings. The real Director authors bounded criteria and roster; the real Manager selects compatible required and optional read-only steps and compiles their immutable Graph. Explicit user assignments remain pins, not factory-generated defaults. Curation triage reads exact Owner-exported pages; the native normalizer alone uses its three scoped proposal tools. Independent model EvalOfficer decisions are compiled after deterministic source/effect checks. Recovery requires a stopped producer and original-actor intent, reuses a retained semantic decision after report loss, and preserves unmet/RemainingWork without repeating the producer.

Independent Curation assessment receives the selected proposal's actual Owner creation receipt and live human-request lifecycle, allowed actions, evidence references, expiry and target digest; an approval-required flag is not a substitute for that gate evidence. Full satisfied and historical checkpoint rationales remain decision evidence. Only current top-level unmet/not-run reasons that become Core `RemainingWork.gaps.summary` inherit its 512-character limit; no rationale is truncated and no missing work is forced to pass.

`application/research_work.py` supplies `knowledgeos.cited_research_team` on `evidence-research`, with a dedicated ResearchManager, required retriever/synthesizer, admitted optional read-only teammates and independent model EvalOfficer. Admission binds exact source/question, method and Owner authority. Manager-bounded composition selects the actual sequential Graph and steps within the admitted roster/budgets; there is no unconditional fixed two-call plan or fabricated user assignment. `research_temporal.py` and `research_workflow.py` execute the retained plan through the pinned official plugin. Research and Curation cannot borrow each other's native route.

Research retrieval exposes only `knowledge_search`, `knowledge_retrieve`, `knowledge_read` and `citation_verify`; empty search never replaces required complete source-page reads. Synthesis consumes validated evidence and exposes only `artifact_submit` for a cited report, not a canonical effect. Method adapters preserve request/tool/trace semantics; `native_runtime.py`, `agent_runtime.py`, `role_policy.py` and `role_binding.py` supply the shared role runtime. The adapter digest hashes the canonical sorted filename-to-raw-byte-SHA256 map of the selected adapter and those four shared files; `agent_policy_digest` separately binds the manifest, COMMON and every role SOUL. Each actual invocation retains model/effort/prompt/session/wire evidence. Independent semantic judgment and final deterministic source/citation/receipt checks remain separate; structural validity never manufactures satisfied criteria.

Research accepts the MCP's bounded result limit and source-narrowing filters without mistaking them for expanded authority. The exact admitted question, generation, lexical mode, zero-hop limit, selected source and fresh Owner-read evidence remain checked. Rejected native responses are retained as attempts, not executable predecessor evidence. Shared native Team Graph branches are asynchronous so Workflow routing never invokes a thread executor inside Temporal.

Native Team stage preparation/auditing, Curation normalization and shared semantic assessment preparation, context validation, compilation and retention run synchronous Owner work outside the asyncio loop. Assessment Activities also offload dispatch reads and final Owner recording; model invocation stays on its ordered transport's existing loop. These boundaries preserve raw attempts, exact revision checks and proposal registration. The existing heartbeat deadline is unchanged. Workflow routing remains asynchronous and never uses a thread executor. Optional readers may inspect exact artifacts already bound to their own Work, never an arbitrary model-selected artifact.

Authoring adapters copy Owner-supplied original excerpts and hashes; the Owner creates the proposal envelope and its derived digests. Project-review and boundary producers use the Owner-provided request digest as their idempotency key. Boundary evidence distinguishes the selected current bytes from the verified backup/recovery preimage rather than asking a model to invent a preimage identity.

Native metadata-family submissions return an Owner-computed `candidate_digest` over validated canonical candidate JSON, distinct from the rendered artifact's `content_digest`. The current EvalOfficer invocation independently assesses that candidate against exact source and registry evidence; a previous copy of its own assessment is not a prerequisite. Combining metadata and relation candidates into Pending still requires both completed independent Work assessments, and daily provisional review remains a separate Owner operation.

The native host validates invocation identity and preserves actual role/tool evidence; it does not discard a completed model response because the Owner refused a tool call. The Owner retains that attempt before checking source, scope, receipts and method semantics, and only validated evidence can become executable predecessor evidence. Ordinary tool refusal is therefore inspectable without masquerading as a missing transport result. Project retrieval accepts public corpus/type filters behind the MCP's selected-source clamp while preserving exact query, generation, zero-hop and path pins.

Retained model evidence is normal Operation State, not a reason to reject new Work at an arbitrary whole-journal byte ceiling. The journal retains regular-file, private-mode, writer exclusion, exact-preimage, generation and atomic-fsync checks; network/tool payload bounds are separate. Ordinary admission does not require deleting earlier Work or unknown outcomes to make room.

Receipts referenced by retained Owner intents remain durable even after completion; the 12-hour transient observation cache is not an effect-evidence retention policy. Completed Boundary report export checks the exact frozen bytes, effect receipt and retained input snapshot, not a new diagnosis or expired Gateway admission. New admissions and effects still validate current evidence; reading a historical plan neither reauthorizes it nor permits canonical apply.

Ontology analysis may read all three authoritative registries; harmless read order or repetition is not an authority boundary. Coverage still requires every source page and all required registry evidence, and a producer creates only one final artifact. Metadata candidate content has exactly `source_reference`, `registry_digest`, `fields`, `evidence`; source/registry provenance and returned candidate digests remain in Owner evidence, not payload aliases. Project readers receive concrete pinned argument objects so report-period dates do not silently change the query.

Manager planning distinguishes completion evidence from prerequisites: an input obtained by an admitted earlier stage or declared human gate need not already exist before its Graph is composed. Genuine missing authority can still produce a question or rejection, whose actual rationale remains in the failure. Native Steering Profile failures report through the existing Owner uncertainty boundary only for the exact active native Run; they do not leave an apparently active attempt, retry a producer or change another Run.

The Owner supervisor persists a separate native command delivery fence before sending an accepted control/steering command. These records use `delivery_state`, not the expiring proposal intent's `state`/`recorded_at` schema, and remain durable through journal maintenance. A received command without a committed delivery fence has not been sent by this supervisor; an unknown committed fence is observation-only, never permission to resend. Owner restart retains the original command and native Run. On an installed Owner process failure, the host driver exposes its existing stderr and exit status in the private service log instead of discarding the cause.

Project Eval receives the exact retained Work/Graph/evidence identities and effective Owner read bounds. The admitted Team session restricts retrieval, Base and task reads to one selected source before evaluation; empty caller Base filters do not mean unrestricted Vault access. The review period is an interpretation/reporting window, not a claim that `task_query` executed a nonexistent date filter or inferred completion timestamps. Independent assessment still judges period use and content against actual cited evidence; this scope explanation is not a semantic acceptance flag.

Gateway Work uses the actual current accepted Gateway disclosure as Director, Manager and Eval input. Its local Vault source is an anchor, not foreign plaintext. A references-only disclosure supports a useful provenance inventory and missing-content/action plan, not invented measurements. Structured Owner receipt/resource values outrank fallible teammate prose; models copy those values while the Owner performs cryptographic/currentness checks. Admission authorizes only the scoped Pending proposal, not semantic acceptance, human approval or canonical application.

`make research-team-smoke` runs the selected native composition; actual call and Activity counts depend on its admitted plan. The [historical disposable native evidence](../../../Tmp/knowledgeos-native-research-2026-10-31/trace-run.json) retains its original two-specialist, deterministic-assessment scope and is not proof of the current model-decision cutover. Use `RUNTIME.md` for prerequisites and `PROJECT_STATE.md` for actual current acceptance. No generic Research retry/recovery/control, canonical apply or GUI adoption follows from that older pass.

`application/curation_continuation.py` uses a separate method on the same Curation Manager. Initial triage and the Pending-producing successor remain distinct stage groups. A real independent assessment must report the genuinely unexecuted proposal criterion as `not_run` and retain exact RemainingWork; the same Manager composes only its authorized immutable successor. Optional read-only steps remain within the Director-admitted roster and cumulative segment/Profile/gap budgets. Exhaustion stops before additional inference/effects. The separate method-bound native Workflow and official plugin graphs preserve predecessor/trigger lineage; combined continuation/recovery is not implied.

The trusted `control_checkpoint=True` admission flag selects a separate native control route on the continuation method. `CurationRunControl` opens a revision-bound wait only after independent initial evidence and before any model/proposal effect. CANCEL terminates at that boundary or while paused. One applied PAUSE produces a fresh paused target; only exact applied RESUME authorizes the existing immutable successor. Both receipts survive idle Worker reconstruction without resetting evidence, lineage or consumed budgets. Native Activities and owner commits reauthorize current authority; SDK-free MCP/proposal checks independently require the durable release proof. `make team-control-smoke` covers cancellation plus actual model continuation after resume, historical receipts and client response-loss reconciliation, not generic or in-flight control.

The controlled binding additionally permits one owner-prepared/adopted Continue-As-New at its idle checkpoint. A separate durable handoff pins the original Work and command snapshots and authorizes one replacement native Run, without rewriting the original checkpoint target or logical IDs. Pending commands, cached applied receipts, immutable evidence and consumed budgets survive; the replacement does not rerun initial Profiles. `make team-rollover-smoke` exercises pending RESUME plus cached PAUSE, native Run fencing, the existing successor and replay of both histories. Rollover does not widen Profile authority or grant a new segment budget.

Role homes and read-only model access do not grant Work authority. Required method stages and optional read-only steps receive only their exact Owner tool grants; no producer can approve/apply or select another Work through arguments. Remote execution excludes local-only, denied and confidential sources. Maintained COMMON plus 37 SOULs and explicit route policy are linked in the [profile guide](../../../Runtimes/README.md#모델-정책과-13개-home-정렬). Actual model traces stay owner-private; current source, installed activation, real-model method completion, external transport and GUI observations remain separate evidence. Computer Use is delegated to Codex, not performed by this implementation.
