    KnowledgeOS 안에서는 무슨 일이 일어나는가

    노트에서 정리를 누르면 어떤 모델이 무엇을 읽을까요? 강화 보고서는 어떤 중간 작업을 거쳐 만들어질까요? 예약 작업과 Temporal은 어디에서 만나고, 어떤 기능은 왜 모델 없이 끝날까요?

    이 위키는 그 질문에 답합니다. 설계 원칙을 다시 배우는 대신, 실제로 구현된 기능을 한 번의 입력부터 결과까지 따라 읽는 것이 출발점입니다.

    실행 구조를 먼저 보고 싶다면#

    구조는 기능들이 함께 사용하는 실행 장치의 지도입니다. 아홉 모델 Profile과 발송 전용 kos-ops, Manager가 고르는 Graph의 실제 범위, Temporal Workflow와 Activity, 파일에 결과를 쓰는 시점을 설명합니다.

    여기서 특히 구별할 것은 세 가지입니다.

    • 요청과 Work는 다릅니다. 검색·관찰처럼 바로 결과를 반환하는 요청이 있고, Work를 만들어 Temporal에서 실행하는 요청이 있습니다.
    • 역할과 Profile은 다릅니다. scout 같은 정적 역할은 Python 코드로 실행되며 Hermes Profile이 없습니다. 모델 역할만 각자의 kos-* Profile을 사용합니다.
    • Graph와 Temporal은 같은 것이 아닙니다. Graph는 한 구간 안에서 누가 어떤 순서로 일하는지를 정하고, Temporal은 그 실행 단계와 결과의 이력을 이어 갑니다.

    이 위키에서 기능을 읽는 방법#

    각 기능은 실제 예시와 처리 순서로 설명합니다. 필요할 때 Profile·Graph·Temporal 연결을 짚고, 결과 파일과 달라지는 분기를 이어서 설명합니다. 페이지 끝의 근거 링크와 인수 표는 더 확인하고 싶을 때 쓰는 참고 자료입니다. 본문을 이해하기 위해 코드를 열 필요는 없어야 합니다.

    소스로 확인한 동작과 실제 호스트에서 관찰된 범위는 다릅니다. 현재 상태에는 설치·실행·장치 관찰의 근거를, 로드맵에는 아직 확인하지 않았거나 구현하지 않은 것을 모았습니다. 집필 기준은 운용 원칙에 있습니다.
