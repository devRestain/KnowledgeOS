    용어 사전

    KnowledgeOS 문서에는 영어 용어가 그대로 쓰입니다. 코드·명세와 같은 단어를 쓰려고 번역하지 않은 것이므로, 여기서 한 번씩 풀어 둡니다. 정의는 원본 문서에서 가져왔고, 원본에 정의가 없어 풀어 쓴 것은 [해석] 으로 표시했습니다. 모르는 말이 나오면 이 페이지로 돌아오세요.

    명세가 공식으로 정의한 용어#

    아래는 docs/CAPABILITIES.md의 "Shared terms" 원문입니다.

    원본: docs/CAPABILITIES.md · Shared terms

    Shared terms#

    • Request: a Thin Client command, console action, CLI command, scheduled job run or Gateway submission, identified by a stable request ID.
    • Work: one Director-admitted request. It records its actor, target (Officer or Team), snapshotted inputs, segments, role invocations, effects and assessment.
    • Step: one role invocation inside a segment. It is either static (Owner code) or model (a Hermes role profile).
    • Handoff: a teammate's intermediate artifact, readable by later teammates in the same Work.
    • Report: a create-only Markdown note in 01_AI_Review/Reports/.
    • Proposal: a change set for one target note in 01_AI_Review/Proposals/, applied only by the user. It is create-only except for exact-preimage regeneration of an unchanged Owner-written proposal (Blueprint §5.6, §6.2).
    • Autofix: a standardization change written directly under capability C2 rules: deterministic rules 1-8 and rule-9 values System One decided with sufficient confidence.
    • Attention item: something that needs the user's eye. It is shown either as a Bases view over Vault metadata or as a computed entry in the console and the digest. It is never stored as a note.
    • System One: the Owner's fast closed-set judgment service (below). It answers typed questions; Owner code acts on the answers.

    요청과 작업#

    용어 뜻 더 보기
    Request(요청)Thin Client 명령, 콘솔 동작, CLI 명령, 예약 작업 실행, Gateway 제출 중 하나. 안정적인 요청 ID가 붙습니다C11
    Admission(접수)Director가 요청을 받아들여 Work로 만드는 일. 정형 요청은 코드가, 자유 요청만 모델이 초안을 만듭니다구조
    Work(작업)Director가 접수한 요청 하나. 실행한 주체, 대상, 입력 스냅숏, 구간, 역할 호출, 효과, 평가를 기록합니다구조
    WorkSpec접수된 작업 명세: 대상(Officer 또는 Team), 카탈로그에서 온 기준, 예산, 입력 범위. 모델은 기준을 쓰지 못합니다구조
    Step(단계)구간 안의 역할 호출 하나. static(Owner 코드) 또는 model(Hermes 역할 profile)구조
    Graph / Segment(구간)Manager가 정한 "어느 팀원이 어떤 순서로 + 평가 위치". 승인된 구간은 바뀌지 않고, 부족하면 후속 구간이 더해집니다구조
    Handoff(인계물)팀원이 남기는 중간 산출물. 뒤의 팀원이 같은 작업 안에서 읽을 수 있습니다C1, C4
    Budget(예산)한 작업이 쓸 수 있는 양. 기본값은 Team 2구간·생산자 호출 6회, Officer 1구간입니다구조
    RemainingWork평가에서 기준에 못 미친 "남은 일". 같은 Manager가 이것만 다루는 후속 구간을 짭니다ENH-6
    CompletionAssessment평가 결과(만족·미충족 등)의 기록. Owner가 EvalOfficer의 판정과 static 검사를 모아 만듭니다구조
    Corrective turn(교정 턴)모델 제출이 형식에 어긋날 때 진단과 함께 한 번 더 주는 기회. 두 번째 실패는 단계 실패입니다ENH-2
    Authority violation(권한 위반)모델이 자기 권한 밖(기준·예산·경로 정하기, EvalOfficer에게 지시하기 등)을 시도하는 것. 교정 턴 없이 즉시 거절됩니다ORG-5
    TeamReview작업이 끝난 뒤 Manager가 팀원 성과를 평가하고 개선 제안(최대 3개)을 남기는 기록. 조언일 뿐 역할을 바꾸지 못합니다ENH-7

    역할#

    용어 뜻 더 보기
    Owner권한과 효과의 주인. 정책 판단, State, 파일 쓰기, 기록, 알림을 맡고 내용은 판단하지 않습니다. 호스트에서 필요할 때 켜지는 사용자 서비스입니다구조
    Director접수 담당. 요청을 WorkSpec으로 바꿉니다구조
    Manager팀의 Graph를 짜고 후속 구간과 TeamReview를 맡습니다. CurationManager(정리 팀)와 ThinkingManager(강화 팀)가 있습니다C1, C4
    Teammate(팀원)한 종류의 중간 산출물만 만드는 역할. 정리 팀 scout·classifier·linker, 강화 팀 retriever·connector·challenger·synthesizerC1, C4
    Team(팀)Manager 한 명과 팀원들. 정리 Team(C1)과 강화(Thinking) Team(C4)이 있습니다구조
    Officer팀 없이 혼자 결과 하나를 책임지는 static 역할. StandardizationOfficer, StewardshipOfficer, EmbeddingOfficer. 앞의 둘은 설정 시 System One에게 선택지·확률 질문을 합니다C2, C3, C5
    EvalOfficer독립 평가자. 모든 작업의 기준을 평가하고, 결과를 만들거나 고치지 않습니다. static 검사는 항상, 의미 기준만 모델이 판단합니다구조
    Scheduler선언된 예약 작업을 트리거하는 Owner 안의 서비스C7
    Notifier만들어진 알림을 전달하는 호스트 서비스. 내용은 만들지 않습니다C8
    System OneOwner가 OpenAI Decisions API(모델 gpt-6-luna)에 직접 묻는 빠른 선택형 판단 서비스. 역할(role)이 아니고 Hermes profile도 없습니다. 고정된 선택지 중 하나(choice)나 확률(predicate)만 답하며, 쓰지도 글을 짓지도 않고 ai_policy·sensitivity는 결정하지 않습니다. 설정이 없거나 실패하면 모든 기능이 System One 없이 하던 대로 동작합니다C2, C1, C3, C5, C11
    choice / predicateSystem One의 두 질문 형식. choice는 정해진 값 중 하나와 none_of_these(어느 것도 아님)를 고르게 하고, predicate는 "이 문장이 참인가"의 확률을 답하게 합니다C2, C5
    min_confidenceSystem One의 choice 답을 쓰는 최소 확신도(기본 0.7). 미만이거나 none_of_these이면 아무것도 바꾸지 않습니다. 실제 노트로 조정할 시작값입니다C2, C11
    Vetted(거름 통과)의미 이웃이 System One의 "정말 관련 있는가" 판정(related_min_probability 이상)을 통과해 vetted: true로 표시된 상태SRC-9

    저장소와 실행#

    용어 뜻 더 보기

    CoreAgentFabric의 공통 계약과 스키마. KnowledgeOS는 수정하지 않고 config/core-adoption.json으로 고정해 따릅니다구조
    Vault사용자의 KnowledgeHub 노트 저장소. 사용자의 것이며 GitHub private repo로 백업됩니다구조
    State요청 영수증, 작업 기록, 입력 스냅숏, 자동 변경 이력, 알림·Experience outbox 같은 운영 기록(States/Operations/knowledgeos/). 잃어도 지식은 남습니다. 의미 검색 벡터도 여기(<State>/semantic/)에 있습니다구조
    Runtime호스트의 Python 실행 환경, Owner 바인딩 설정, LaunchAgent 로그, 생성한 Hermes 배포물. 다시 만들 수 있습니다. 키워드 색인은 메모리에, 의미 검색 벡터는 State에 둡니다구조
    ExOpsOwner의 loopback HTTP 접수 경로. Thin Client·콘솔·CLI가 공유합니다구조
    Temporal작업의 내구성 있는 수명을 맡는 실행 서버. 호스트 loopback에만 공개됩니다구조

    Hermes모델 역할을 실행하는 에이전트 런타임 [해석: 원본이 profile·route·skill·memory로 다루는 대상]구조

    kos-ops모델도 스케줄러도 없는 발송 전용 profile. Discord 알림만 보냅니다C8
    HermesTrace근거 있는 사건(Experience 후보)을 받는 다른 OperationC9
    InterOpsOperation 사이의 정보 교환 통로. Gateway 접수·조회와 Experience 전달이 이를 거칩니다C10
    Ollama의미 검색용 임베딩을 만드는 로컬 서버. Owner가 loopback으로 직접 부릅니다C3
    LaunchAgent / launchdmacOS 사용자 서비스 등록 방식. Owner는 RunAtLoad·KeepAlive를 끈 채 등록되어 사용자가 시작할 때만 켜집니다C11
    loopback127.0.0.1. 같은 컴퓨터 안에서만 닿는 주소구조
    healthOwner가 GET /api/health로 알려 주는 상태. Owner 시작·중지는 이것이 실제로 응답하는지로 결과를 판정합니다C11

    개인정보와 안전#

    용어 뜻 더 보기
    ai_policy노트마다 모델·자동화의 사용 범위를 정하는 속성. remote_ok·ask(기본)·local_only·deny구조
    remote_ok예약 작업을 포함해 모델이 사용할 수 있음. Gateway 조회에도 나갈 수 있음구조
    ask내가 직접 요청한 작업에서만 모델이 사용구조
    local_only로컬 처리와 로컬 모델만구조
    deny읽지도, 색인하지도, 알리지도 않음ORG-3
    sensitivitypublic·personal(기본)·confidential. confidential 노트는 ai_policy가 느슨해도 local_only로 다룹니다. 어긋남은 주의 항목으로 알리되 사용자의 값을 고쳐 쓰지는 않습니다 [해석: 원본이 confidential을 이 속성값으로 가리킨다고 읽음]구조
    Preimage바꾸기 직전 파일의 SHA-256. 쓰기 직전 현재 값과 같을 때만 씁니다STD-3
    Stale(낡음)제안을 만든 뒤 대상 노트가 바뀌어 더는 적용할 수 없는 상태. 7일 뒤 지워집니다REV-2
    Receipt(영수증)요청이 기록됐음을 확정한 기록. 응답을 잃으면 클라이언트가 이것을 읽어 결과를 확인합니다REV-4
    Unknown(결과 불명)효과의 결과를 관찰하지 못한 상태. 자동으로 다시 보내거나 돌리지 않습니다NTF-3
    Reconcile(확인 기록)사람이 결과 불명 항목을 직접 확인해 "적용됨/적용 안 됨"을 기록하는 일. 과거 기록은 고치지 않습니다SUR-4
    Snapshot(스냅숏)접수 때 State에 잡아 둔 입력 노트의 정확한 바이트ENH-3
    Fail closed확인할 수 없으면 허용하지 않고 막는 방식 [해석: 원본의 "fails closed"]구조
    Autofix규격화가 노트에 직접 쓴 작은 변경. 결정적 규칙 1~8과, System One이 충분한 확신으로 고른 규칙 9의 값을 포함합니다C2
    Quiet period최근 편집한 노트를 자동 규격화가 건너뛰는 기간(기본 10분)STD-4
    Conflict markerGit 병합 충돌 표시. 있는 노트는 모든 자동화가 건너뛰고 주의 항목이 됩니다DOC-3
    Attention item(주의 항목)사용자가 봐야 할 것. 노트로 저장하지 않고 Bases 보기나 콘솔·요약에서 계산합니다C5
    HumanActionResponse적용·거절·되돌리기·콘솔 동작 같은 사람의 결정을 기록하는 Core 기록. 받음·적용됨·적용 안 됨·불명을 구분합니다C6

    검색#

    용어 뜻 더 보기
    Keyword mode(키워드)한국어·영어 부분 단어 일치. 색인은 메모리에 있습니다SRC-1
    Semantic mode(의미)질문과 각 노트의 가장 가까운 조각(chunk)의 임베딩 유사도(코사인)로 순위를 매기는 검색. 색인이 준비되고 질문을 임베딩할 수 있을 때만 쓰며, 안 되면 "unavailable"이고 키워드로 몰래 대체하지 않습니다SRC-3
    Embedding(임베딩)글을 숫자 벡터로 바꾼 것. 의미가 비슷한 글은 벡터가 가깝습니다 [해석]C3
    Chunk(조각)제목·문단 경계로 자른 약 1,500자 창과 그 줄 범위SRC-7
    Neighbor(이웃)한 노트의 평균 벡터와 충분히 가까운(related_min_score 이상) 노트. 최대 related_neighbors개C3
    Index ready(색인 준비)설정한 모델의 벡터가 노트 하나 이상에 있는 상태SRC-3
    Citation(인용){resource_reference, chunk_locator, chunk_hash}. 어떤 바이트를 읽었는지 증명하며, 주장이 참임을 증명하지는 않습니다C4
    ResourceReference어느 시점의 노트를 가리키는 Core 참조: 노트 ID 또는 경로와, 읽은 정확한 바이트의 SHA-256구조
    Evidence handle(근거 핸들)읽기 도구가 돌려주는 작업별 짧은 핸들(e7 등). 최대 40줄의 정확한 바이트와 위치를 가리킵니다구조
