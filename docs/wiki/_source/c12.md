# C12 데일리 노트 (Daily notes)

데일리 노트는 하루의 메모·할 일·일정·하루 정리를 한 노트에 모아 두고, 끝내지 못한 최상위 체크박스만 다음 데일리 노트로 기계적으로 이어 주는 기능입니다. 내용을 요약하거나 AI 제안을 만들지 않으며([[ORG-8]]), 모든 분류와 파일 쓰기는 정적 규칙으로만 동작합니다([`c12_daily.py`](../../src/knowledgeos/capabilities/c12_daily.py)).

## 실행 주체와 Temporal·Graph 접점

| 항목 | 실제 구현 |
|---|---|
| 트리거 | 예약 작업 `daily`(매일 07:00, 서울 시각), CLI `knowledgeos job run daily` (`daily.run`, `origins: ["user", "schedule"]`, 파라미터 없음) |
| Hermes 모델 프로파일 | **노트 작성·이월에는 없음** (`DailyOfficer` 정적, `EvalOfficer` 정적, System One 미사용). 할 일이 있어 Discord 알림을 보낼 때만 모델 없는 송신 전용 **`kos-ops`** 사용 |
| LangGraph·Temporal 경로 | `WorkWorkflow` (`knowledgeos.work.v1`) 1구간 · 단일 Officer Graph (`[daily_officer, evaluation]`) 실행 후 `DailyOfficer` 완료 단계에서 Vault 쓰기와 알림 처리 (공통 단계는 [[architecture]] 참조) |

## 현실적인 입력 예: 어제 못 끝낸 일과 오늘 노트

오늘이 `2026-11-21`이고 어제 노트에 다음 두 항목이 남아 있다고 하겠습니다.

```markdown
## 할 일
- [ ] #task 초안 검토

## 일정
- [/] 치과 예약
```

오늘 노트가 없으면 새 노트의 **할 일**에 초안 검토를, **일정**에 치과 예약을 넣습니다. 어제 노트에서는 두 항목의 체크박스 칸만 `[>]`로 바뀝니다. 완료 표시가 아니라 “오늘로 넘겼다”는 표시입니다.

같은 “초안 검토” 줄이 그저께 노트와 오늘 노트에도 있다면 오늘에는 더 넣지 않고, 이전 노트의 해당 항목들만 `[>]`로 마무리합니다. 다른 일반 노트에 마감이 지난 `#task`가 있으면 아침 알림에는 포함될 수 있지만, 데일리 인계가 그 일반 노트까지 옮기거나 표시를 바꾸지는 않습니다.

데일리 폴더는 기본 `10_Journal/Daily`이며 `settings.C12.folder`에서 정합니다. 바로 아래의 과거 날짜 파일만 대상입니다. 하위 폴더·미래 날짜·잘못된 날짜 이름·거부 정책·깨진 YAML·충돌 파일은 제외합니다.

## 내부 처리 순서: 스캔 · 4구역 생성 · `[>]` 표시 · 부분 쓰기 안전

1. **접수 범위 선별과 오늘 노트 차단 확인**:
   - Owner는 설정 폴더 바로 아래 파일만 훑어 파일명 줄기가 유효한 `YYYY-MM-DD`이면서 오늘(`2026-11-21`)보다 이전인 노트를 날짜 오름차순으로 고릅니다. `deny`(또는 퇴역 정책 값)·충돌 마커·UTF-8/YAML 오류·제외 경로가 있거나 열린 체크박스가 하나도 없는 파일은 대상에서 뺍니다.
   - 만약 오늘 파일 `10_Journal/Daily/2026-11-21.md`가 이미 존재하는데 `deny`·충돌·깨진 YAML 같은 차단 사유가 걸리면 "오늘 차단됨" 상태만 표시하고 **입력 스냅숏을 한 장도 잡지 않습니다**. 따라서 차단된 오늘 노트는 State로 복사되지 않고 쓰기나 알림도 일어나지 않습니다.
2. **항목 스캔과 일정·할 일 분류**:
   - `DailyOfficer`는 접수 때 확보한 스냅숏 바이트만 읽습니다. 삼중 백틱 코드 블록과 `<!-- ... -->` 주석은 건너뛰고, 가장 가까운 앞쪽 Markdown 제목이 `일정`으로 시작하면 일정으로, 그 밖의 위치(제목 이전·`할 일`·`작업`·`메모` 등)는 모두 할 일로 분류합니다.
   - 최상위 열린 체크박스(`- [ ]`, `* [/]`, `1. [ ]`, `2) [/]`처럼 공백이나 `/`가 채워진 항목)와 바로 뒤에 이어지는 비어 있지 않은 들여쓴 연속 줄을 한 항목으로 묶습니다. 빈 줄이나 들여쓰지 않은 줄이 나오면 항목이 끝납니다. 완료(`[x]`), 취소(`[-]`), 이미 넘김(`[>]`), 내용 없는 빈 체크박스, 일반 글머리표, 하위 들여쓰기 체크박스 자체는 이월하지 않습니다.
3. **중복 제거와 오늘 노트 4구역 구성**:
   - 날짜순 → 문서순으로 항목을 모으되, **항목의 첫 줄 문자열**(줄바꿈 제외)이 오늘 노트에 이미 똑같이 들어 있으면 오늘 노트에 또 끼워 넣지 않습니다. 단, 오늘에 이미 있다는 뜻이므로 **이전 노트의 해당 체크박스는 여전히 `[>]`로 바꿀 목록에 포함합니다**([[DAY-2]]). 여러 이전 노트에 같은 첫 줄이 겹쳐 있어도 오늘에는 한 번만 들어갑니다.
   - **오늘 노트가 없을 때**: UUIDv4 `id`, `type: daily`, `created`, `tags: [journal/daily]`, `ai_policy: approve`, `sensitivity: personal`의 머리말과 템플릿 `T10_Daily.md`와 똑같은 **4개 구역**(`## 메모`, `## 할 일`, `## 일정`, `## 하루 정리`)을 LF(`\n`) 줄바꿈으로 만듭니다([[DAY-5]]). 이월된 할 일은 `## 할 일`의 예시 주석 바로 아래에, 이월된 일정은 `## 일정`의 마지막 예시 주석 바로 아래에 들어가며 비어 있는 구역은 템플릿 원형 그대로 둡니다.
   - **오늘 노트가 이미 있을 때**: 기존 줄과 순서를 한 줄도 건드리지 않습니다. 일정은 첫 `일정` 제목 구역의 마지막 비어 있지 않은 줄 뒤에, 할 일은 첫 `할 일`(없으면 `작업`) 제목 구역의 마지막 비어 있지 않은 줄 뒤에 끼워 넣습니다. 해당 구역이 없으면 파일 맨 끝에 `## 일정`이나 `## 할 일`을 덧붙입니다([[DAY-1]], [[DAY-2]]).
4. **정적 평가 검증**:
   - 정적 `EvalOfficer`가 접수된 스냅숏만으로 같은 결과를 다시 계산해 새 노트의 UUIDv4 형식, 이월 항목 출처, 이전 노트에서 `[>]` 문자만 바뀌는지 대조합니다. 한 바이트라도 다르면 `unmet`으로 멈추고 아무것도 쓰지 않습니다.
5. **오늘 먼저, 원본은 나중 — 부분 쓰기 안전 순서**:
   - **먼저 오늘 노트 쓰기**: 오늘 노트가 없었으면 정확히 `2026-11-21.md` 경로로만 배타 생성합니다. 생성 직전 사용자가 오늘 노트를 새로 만들어 두었더라도 `2026-11-21 2.md` 같은 접미사 파일을 만들거나 덮어쓰지 않고 `not_applied`로 남긴 채 **이전 노트에 `[>]`를 표시하지 않고 종료**합니다. 이미 있던 오늘 노트는 접수 때의 SHA-256 지문이 같을 때만 교체합니다.
   - **그다음 이전 노트마다 개별 `[>]` 표시**: 오늘 쓰기가 반영되었거나 새로 넣을 항목이 없을 때만 각 이전 노트를 순서대로 확인해 체크박스 칸만 `[ ]`·`[/]`에서 `[>]`로 바꾸고 줄바꿈 방식(`\r\n`·`\n`)과 나머지 바이트는 그대로 유지합니다.
   - **이전 노트 하나가 실행 도중 편집된 경우**: 예컨대 `2026-11-19.md`는 `[>]` 표시가 성공(`marked`)하고 `2026-11-20.md`는 사용자가 방금 수정해 지문이 어긋났다면, `2026-11-20.md`만 건너뛰고 `not_applied`에 남깁니다([[DAY-3]]). 다음 실행 때 `2026-11-20.md`의 남은(또는 새로 적은) 항목을 다시 계산하며, 오늘 노트에 이미 들어간 항목은 중복 삽입하지 않고 원본만 `[>]`로 마무리합니다.

## 개인정보 필터링과 아침 할 일 알림

파일 쓰기가 끝나면 스냅숏이 아니라 **디스크에 있는 현재 오늘 노트**를 다시 읽어 아침 알림을 준비합니다.

1. **날짜·노트 ID별 1회 중복 방지**: 알림 식별자를 `daily/YYYY-MM-DD/<오늘 노트 id>`로 삼아 이미 보낸 알림(`notices/*.json`)이 있는지 확인합니다. 같은 날 두 번째 실행에서는 같은 알림 ID만 돌려주고 다시 보내지 않습니다. 단, 오늘 노트를 지웠다가 새로 만들면 `id`가 새로 발급되므로 알림이 다시 한 번 나갈 수 있습니다. 오늘 노트가 `deny` 등으로 차단되면 알림을 보내지 않습니다.
2. **공개 가능한 `#task` 모으기**:
   - 먼저 오늘 노트의 모든 구역에서 `#task` 태그가 붙은 열린 최상위 체크박스만 문서 순서대로 모읍니다. `#task`가 없는 일정(`1. [/] 치과 예약`)은 빠집니다.
   - 이어서 데일리 폴더·`99_System/`·`01_AI_Review/` 바깥의 모든 노트를 현재 디스크 기준으로 읽어, 현재 `ai_policy`가 `deny`가 아닌 노트에서만 마감일(`📅 YYYY-MM-DD`)이 오늘 이전이거나 오늘인 열린 `#task`를 추가합니다. **`deny` 노트는 제목·내용은 물론 건수로도 절대 언급하지 않습니다**([[DAY-4]]).
3. **할 일 이름 정제와 발송**: 체크박스·`#task`·날짜·우선순위·반복 표시를 걷어 내고 할 일 이름과 일반 태그만 남깁니다. 알릴 것이 없으면 보내지 않습니다. 있으면 인사와 최대 20개 이름, 초과 건수와 마무리 문구로 메시지를 만듭니다. 일반 노트의 마감 항목에는 “오늘까지” 또는 “기한이 지났어요”를 붙입니다. **노트 제목·경로·링크는 넣지 않습니다.** 완성된 메시지는 모델 없는 발송용 `kos-ops`가 한 번 보내며, 전송 결과를 모르는 경우 자동 재전송하지 않습니다.

- 공통 정책·쓰기 안전 원칙은 [[architecture]]를 참고하세요.
